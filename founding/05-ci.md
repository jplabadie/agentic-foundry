# CI

The workflow is `.github/workflows/ci.yml`. It is part of the contract.

## Jobs

The job ids are exactly `requiredChecks` in the manifest. Today those are `bedrock` and `contract`.

- `bedrock` runs `node scripts/bedrock.mjs`.
- `contract` runs the node test that the code reads the manifest instead of a handwritten list.

## Rules that the workflow itself must keep

- `permissions` is `contents: read`. The workflow does not write back to the repository.
- Actions are referenced by a 40-character commit SHA, with the version in a trailing comment.
- The token is not printed. Secrets are not interpolated into a log step.
- Pull requests from forks use the `pull_request` event, never `pull_request_target`, so untrusted code does not receive a write token.
- Concurrency cancels a stale run on the same ref.

## What to require on the branch

After the first green run, the default branch should require the check names `bedrock` and `contract`. The repository cannot require a check that has never run. Turn that setting on once CI has reported them.
